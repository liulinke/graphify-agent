## 1. 引言

### 1.1 编写目的

本文档面向研发团队，定义一个由 AI Agent 驱动的「网络信息采集 → 知识图谱构建 → 图形化与自然语言查询」系统的功能需求、非功能需求与技术架构。文档可直接用于系统设计、任务拆分、接口约定与测试验收。

### 1.2 项目背景

用户希望构建一个**随时间持续演进的知识库**。信息来源为公开网络，需要每日增量采集；采集结果以**知识图谱**形式存储于 Neo4j（图谱构建层称为 Graphify）。用户既可在图谱上做**图形化交互查询**（点击节点逐层展开），也可用**自然语言提问**进行检索。典型场景为「中国机器人行业股票分析」这类随行情、新闻、统计数据不断更新的领域知识库。

### 1.3 范围

系统包含但不限于：

- 多知识库管理（每个知识库独立隔离）。
- 自然语言驱动的采集任务定义与每日定时增量采集。
- URL 发现、网页抓取、内容抽取、跨日去重。
- 实体/关系抽取，写入 Neo4j 知识图谱（含时序属性）。
- 图形化探索查询与自然语言查询（NL2Cypher）。

**不在本期范围**：交易下单/资金操作、付费数据源购买、移动端原生 App、多租户计费体系。

### 1.4 术语与缩略语

| 术语 | 说明 |
|---|---|
| KB（Knowledge Base） | 知识库，用户创建的一个独立采集+图谱命名空间 |
| Agent | 由 LLM 驱动、可规划与调用工具的自动执行单元 |
| Graphify | 本系统中负责"非结构化文本 → 图谱三元组"的图谱构建模块 |
| 实体（Entity / Node） | 图谱节点，如公司、人物、产品、指标 |
| 关系（Relationship / Edge） | 图谱中节点之间的有向边，如"供应商""属于行业" |
| NL2Cypher | 自然语言到 Neo4j Cypher 查询语句的转换 |
| SimHash / MinHash | 用于近似去重的局部敏感哈希算法 |
| 时序属性 | 节点上随时间变化的属性快照，如股价、销量 |
| 采集源（Source） | 一个被抓取的 URL 及其元数据 |

### 1.5 参考

- Neo4j 5.x Cypher Manual
- W3C PROV-O（数据来源溯源建模参考）
- robots.txt 协议（RFC 9309）

## 2. 总体描述

### 2.1 产品愿景

一句话：**"用自然语言描述你想持续追踪的领域，系统每天替你把网上的新信息收进一张可点击、可问答的知识图谱。"**

### 2.2 核心能力概览

1. **意图理解**：把用户的自然语言采集指令解析为结构化采集计划（主题、范围、上下游产业、来源数量上限等）。
2. **每日增量采集**：定时触发，发现新 URL、抓取、抽取、去重，仅把"新增/变化"的信息并入图谱。
3. **图谱构建**：抽取实体与关系，带溯源与时间戳写入 Neo4j。
4. **双模查询**：图形化逐层探索 + 自然语言问答。

### 2.3 用户角色

| 角色 | 描述 | 主要诉求 |
|---|---|---|
| 知识库拥有者 | 创建/配置 KB，下达采集指令，查看图谱 | 准确、不重复、可追溯 |
| 分析师（查询者） | 在图谱上探索、提问 | 快速定位实体与关联 |
| 系统管理员 | 监控任务、配额、数据源健康 | 稳定、可观测 |
| Agent（系统自身） | 自动执行采集与图谱构建 | 工具可靠、可回滚 |

### 2.4 运行环境（建议）

- 后端：Python（Agent / 抽取 / 调度）+ FastAPI。
- 图数据库：Neo4j 5.x（社区或企业版）。
- 任务队列：Celery / Redis 或 Temporal（推荐 Temporal，便于长流程编排与重试）。
- 向量检索：可选（pgvector / Qdrant），用于语义去重与 RAG。
- 前端：Web（React + 图可视化库，如 G6 / Cytoscape.js / Neo4j NVL）。
- LLM：可插拔（用于意图解析、实体抽取、NL2Cypher、答案生成）。

### 2.5 约束与假设

- 仅采集**公开可访问**网页，遵守 robots.txt 与目标站点条款。
- "来源数量=100"指**本次采集计划目标抓取的去重后 URL 上限**，实际入图条数可能更少（部分被去重/抽取失败）。
- LLM 抽取存在不确定性，需置信度阈值与人工复核机制兜底。
- 金融数据仅作信息聚合，**不构成投资建议**。

### 3.2 关键模块职责

| 模块 | 职责 | 关键技术点 |
|---|---|---|
| 采集 Agent 编排器 | 解析指令 → 生成采集计划 → 调度抓取/抽取工具 → 汇总结果 | LLM 规划、工具调用、状态机 |
| URL 发现器 | 基于主题与上下游词表，通过搜索/站点扩展产出候选 URL | 搜索 API、站点地图、链接扩散 |
| 抓取器（Fetcher） | 下载网页，处理 JS 渲染、反爬、限速、robots | 无头浏览器 + 静态抓取双通道 |
| 去重器（Dedup） | URL 级 + 内容级 + 语义级三层去重 | 规范化 URL、SimHash、向量相似度 |
| 内容抽取器 | 正文抽取、结构化字段抽取（股价、销量等） | 可读性算法 + LLM 抽取 |
| Graphify 图谱构建 | 文本 → 实体/关系/时序属性 → 写入 Neo4j | Schema 约束、实体消歧、溯源 |
| 查询子系统 | 图形化探索 API + NL2Cypher + 答案生成 | Cypher 模板、LLM、防注入 |
| 调度/编排 | 每日定时、长流程重试、幂等、回滚 | Temporal/Celery、幂等键 |

### 3.3 数据流（一次每日采集）

```
触发(定时/手动)
   → 载入KB采集计划(主题/上下游/源上限N)
   → URL发现(产出候选, 数量>N以备去重损耗)
   → URL级去重(剔除已采集URL/规范化重复)
   → 抓取(并发, 限速, 失败重试)
   → 内容级去重(SimHash) + 语义级去重(向量)
   → 内容抽取(正文+结构化字段)
   → 实体/关系抽取(LLM, 带置信度)
   → 实体消歧/对齐(与现有图谱节点匹配)
   → 写入Neo4j(新增节点/边 + 时序属性快照 + 溯源)
   → 生成采集报告(新增/去重/失败统计)
```

## 4. AI Agent 设计

### 4.1 Agent 总体形态

系统采用**多 Agent 协作 + 编排器**模式，而非单体大循环，以保证可观测、可重试、可单测：

- **Planner Agent（规划）**：把自然语言指令转为结构化《采集计划》。
- **Collector Agent（采集执行）**：按计划调度工具完成发现/抓取/去重/抽取。
- **Graph Builder（图谱构建，Graphify）**：抽取三元组并写库。
- **Query Agent（查询）**：处理自然语言问题，生成 Cypher 并组织答案。

编排器（Orchestrator）负责串联，使用工作流引擎保证幂等与重试。

### 4.2 工具（Tools）清单

Agent 可调用的工具均为受控函数，禁止任意代码执行：

| 工具 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `search_urls` | 关键词、数量 | URL 列表 + 元数据 | 主题与上下游词扩展 |
| `fetch_page` | URL | HTML/正文、状态码、快照 | 双通道抓取，遵守 robots |
| `check_duplicate` | URL / 内容指纹 | 是否重复 + 命中原因 | 调用三层去重 |
| `extract_content` | HTML | 正文 + 结构化字段 | 可读性 + LLM |
| `extract_graph` | 文本、Schema | 实体/关系/属性（带置信度） | 受 Schema 约束 |
| `resolve_entity` | 候选实体 | 匹配到的已有节点或新建 | 实体消歧 |
| `upsert_graph` | 三元组 | 写入结果 | 幂等 MERGE |
| `run_cypher` | Cypher（只读/受限写） | 结果集 | 查询用，参数化防注入 |

### 4.3 Planner —— 指令解析输出（采集计划 Schema）

Planner 将自然语言解析为如下 JSON（示例对应"中国国内机器人行业股票分析，含上下游，来源 100"）：

```json
{
  "kb_id": "kb_robotics_001",
  "task_type": "collect",
  "domain": "中国机器人行业 / 股票分析",
  "topics": ["机器人行业", "股票分析", "财务数据", "股价"],
  "include_supply_chain": true,
  "supply_chain": {
    "upstream": ["减速器", "伺服电机", "控制器", "传感器", "芯片"],
    "downstream": ["工业自动化", "服务机器人", "汽车制造", "物流"]
  },
  "region": "CN",
  "source_limit": 100,
  "freshness": "incremental",
  "language": ["zh", "en"],
  "schedule": "daily"
}
```

`source_limit=100` 表示**本次采集计划在去重后最多纳入 100 个 URL 来源**。上下游词表由 LLM 结合行业知识扩展，并允许用户在 UI 校正。

### 4.4 Agent 执行的可靠性要求

- **幂等**：以 `(kb_id, normalized_url)` 为键，重复执行不产生重复节点。
- **可重试**：抓取/抽取每步失败可独立重试，不回滚整批。
- **可观测**：每步记录输入、输出、耗时、token 消耗、置信度。
- **可中断/恢复**：长流程支持断点续跑（工作流引擎持久化状态）。
- **护栏**：LLM 抽取结果必须符合 Schema 与置信度阈值，否则进入待复核队列。

## 5. 数据采集与去重（核心需求）

### 5.1 URL 发现

- 输入：主题词 + 上下游词表 + 区域 + 语言。
- 策略：搜索 API 检索、站点地图（sitemap.xml）扩展、已知权威源（财经/行业站点）定向抓取、页面内链有限扩散。
- 输出：候选 URL（数量应 **> source_limit**，预留去重与失败损耗，建议 1.5–2 倍）。

### 5.2 三层去重机制（关键设计）

每日采集不得重复纳入已有信息，采用三层递进去重：

**第 1 层 —— URL 级去重**
- URL 规范化：去除 utm_*、fragment、排序参数，统一协议与大小写、解析跳转后的最终 URL。
- 比对全局/KB 级 `collected_url` 指纹表（持久化），命中即跳过。

**第 2 层 —— 内容级去重（近似）**
- 对正文计算 SimHash/MinHash 指纹；与历史指纹做汉明距离比对（阈值可配置，如 ≤3 视为重复）。
- 处理"同一篇文章被多站转载/镜像"的情况。

**第 3 层 —— 语义级去重（可选，推荐）**
- 对正文生成向量，向量库做近邻检索，余弦相似度高于阈值（如 0.95）判为语义重复。
- 处理"内容改写但实质相同"。

**变化检测（增量更新而非丢弃）**
- 对于"同一 URL 但内容已更新"（如股价页每日变化）：不视为重复丢弃，而是抓取新值，作为**时序属性新快照**写入图谱（见 6.4），原节点保留历史。

### 5.3 去重状态存储

关系库中维护去重相关表：

| 表 | 关键字段 | 用途 |
|---|---|---|
| `source` | kb_id, url, normalized_url, content_simhash, first_seen, last_seen, etag, content_hash | URL 与内容指纹 |
| `dedup_log` | kb_id, url, dedup_level, matched_source_id, ts | 去重审计 |

### 5.4 抓取合规与稳健性

- 遵守 robots.txt 与速率限制；按域名并发限流与退避。
- 双通道：静态 HTTP 优先；需 JS 渲染时用无头浏览器。
- 失败分级重试（网络/超时/反爬），超过阈值标记失败源。
- 原始 HTML 与快照存对象存储，便于复抽与溯源。

## 6. 知识图谱（Graphify + Neo4j）

### 6.1 建模原则

- 实体类型与关系类型受**受控 Schema** 约束，禁止 LLM 自由发明类型（可走"待审类型"流程扩展）。
- 所有节点/边携带**溯源**（来自哪个 source、采集时间、置信度）。
- 随时间变化的数值（股价、销量）建模为**时序属性快照**，保留历史。
- 多 KB 隔离：节点带 `kb_id`，或每 KB 独立数据库/标签。

### 6.2 节点类型（示例，对应机器人行业场景）

| 节点标签 | 关键属性 | 说明 |
|---|---|---|
| `Company` | name, ticker, region, kb_id, aliases | 公司，如"宇树科技" |
| `Industry` | name, kb_id | 行业，如"机器人行业" |
| `Product` | name, category | 产品/品类 |
| `Component` | name, type(upstream) | 上游零部件，如"伺服电机" |
| `Person` | name, role | 人物（高管等） |
| `Metric` | name, unit | 指标定义，如"股价""销量" |
| `NewsArticle` | title, url, publish_date | 科技新闻 |
| `Source` | url, fetched_at, simhash | 采集源（溯源） |
| `MetricSnapshot` | value, ts, currency | 时序数值快照 |

### 6.3 关系类型（示例）

| 关系 | 方向 | 说明 |
|---|---|---|
| `BELONGS_TO` | Company → Industry | 所属行业 |
| `SUPPLIES` | Company → Company | 供应商关系（上游供下游） |
| `PART_OF_SUPPLY_CHAIN` | Component → Industry | 上下游产业归属 |
| `PRODUCES` | Company → Product | 生产产品 |
| `HAS_METRIC` | Company → Metric | 拥有某指标 |
| `HAS_SNAPSHOT` | Metric → MetricSnapshot | 指标的时序快照 |
| `MENTIONED_IN` | Company → NewsArticle | 在新闻中被提及 |
| `DERIVED_FROM` | 任意节点/边 → Source | 溯源 |

### 6.4 时序属性建模（股价/销量历史）

为支持"点击宇树科技看股价历史、历史销量"，数值随时间变化采用快照子图：

```
(:Company {name:"宇树科技"})-[:HAS_METRIC]->(:Metric {name:"股价"})
        -[:HAS_SNAPSHOT]->(:MetricSnapshot {value:..., ts:"2026-06-21", currency:"CNY"})
        -[:HAS_SNAPSHOT]->(:MetricSnapshot {value:..., ts:"2026-06-22", ...})
```

每日采集若发现新值，仅**追加新快照**，天然形成历史曲线，且不与去重冲突。

### 6.5 实体消歧与对齐

- 写入前调用 `resolve_entity`：按名称 + 别名 + ticker + 行业上下文匹配已有节点。
- 命中则 `MERGE` 到同一节点（避免"宇树科技/Unitree"重复建点）；未命中则新建并记录别名。
- 低置信度匹配进入人工复核队列。

### 6.6 写入约束（Cypher 示例）

使用 `MERGE` 保证幂等：

```cypher
MERGE (c:Company {kb_id:$kb, name:$name})
  ON CREATE SET c.ticker=$ticker, c.created_at=datetime()
MERGE (s:Source {url:$url})
  ON CREATE SET s.fetched_at=datetime(), s.simhash=$simhash
MERGE (c)-[:DERIVED_FROM]->(s)
WITH c
MERGE (m:Metric {kb_id:$kb, name:'股价'})
MERGE (c)-[:HAS_METRIC]->(m)
CREATE (m)-[:HAS_SNAPSHOT]->(:MetricSnapshot {value:$price, ts:date($d), currency:'CNY'})
```

建议建立约束/索引：`Company(kb_id,name)` 唯一约束、`Source(url)` 唯一约束、常用属性索引。

## 7. 查询子系统

### 7.1 图形化探索查询

- 初始视图：展示 KB 的核心节点（按度数/重要性排序）。
- 交互：点击节点 → 调用图探索 API → 返回该节点的属性面板 + 一跳邻居（供应商、产品、指标、新闻等）。
- 逐层展开：点击邻居节点（如某供应商）继续展开其更多信息，支持折叠、过滤关系类型、按时间过滤。
- 指标可视化：点击 `Metric`（如股价）渲染其 `MetricSnapshot` 时序曲线。

**节点详情 API（示例）**

```
GET /api/kb/{kb_id}/node/{node_id}/expand?rel_types=SUPPLIES,HAS_METRIC&depth=1
→ { node: {...}, neighbors: [...], edges: [...] }
```

对应底层 Cypher（参数化）：

```cypher
MATCH (n)-[r]-(m)
WHERE id(n)=$node_id AND type(r) IN $rel_types
RETURN n, r, m LIMIT $limit
```

### 7.2 自然语言查询（NL2Cypher）

流程：

```
用户提问
 → 意图/实体识别(LLM, 结合图谱Schema)
 → 生成候选Cypher(只读, 参数化)
 → 安全校验(只读白名单/LIMIT/超时/标签范围)
 → 执行
 → 结果 + LLM组织自然语言答案(附溯源链接)
```

安全要求：
- 仅允许只读查询，禁止 `CREATE/DELETE/SET/MERGE` 进入查询通道。
- 强制 `LIMIT` 与查询超时；限制可访问标签在当前 KB。
- 生成的 Cypher 必须参数化，防注入。
- 答案需返回所依据的节点/Source，做到可溯源。

### 7.3 两种查询的关系

图形化探索与自然语言查询底层共用同一图谱与同一 Cypher 执行层；前者由 UI 交互生成模板化 Cypher，后者由 LLM 生成并经安全校验。

## 9. 非功能需求（NFR）

| 类别 | 需求 |
|---|---|
| 性能 | 单 KB 单日 100 源采集在合理时间内完成（目标 < 30 分钟，取决于站点）；节点单跳展开响应 < 500ms（缓存命中）。 |
| 可扩展性 | 抓取与抽取可水平扩展（队列 + 多 worker）；支持多 KB 并行。 |
| 可靠性 | 流程幂等、断点续跑；单步失败不影响整批；关键状态持久化。 |
| 数据一致性 | 写入使用 MERGE 幂等；去重指纹与图谱写入在同一事务边界内对齐。 |
| 可观测性 | 全链路日志、指标（采集量/去重率/失败率/token 消耗）、追踪。 |
| 安全 | 查询通道只读、参数化、防注入；KB 数据隔离；访问鉴权与配额。 |
| 合规 | 遵守 robots.txt 与站点条款；保留溯源；金融信息附"非投资建议"声明。 |
| 可维护性 | Schema 受控且可版本化；工具/Agent 可独立单测；Prompt 版本管理。 |
| 成本控制 | LLM 调用可降级/缓存；候选 URL 倍率可配置以平衡覆盖与成本。 |

## 10. 用例与时序（对应给定 USER CASE）

### 10.1 用例总览

| 天 | 用户动作 | 系统行为 | 去重要点 |
|---|---|---|---|
| 第 1 天 | 新建 KB，NL：采集中国机器人行业股票分析（含上下游），来源 100 | Planner 生成计划 → 发现/抓取/抽取 → 建图（首批，无历史可去重） | 建立初始 source 指纹库 |
| 第 2 天 | NL：同主题再次采集，来源 100 | 增量采集 → 三层去重剔除已采集 → 仅纳入新增/变化；股价等追加新快照 | 跨日去重 + 变化检测 |
| 第 3 天 | NL：采集机器人行业科技新闻与统计数据，来源 100 | 新主题维度采集 → 去重 → 新增 NewsArticle/统计指标并关联已有公司/行业 | 与已有图谱对齐去重 |
| 第 4 天 | 图谱上点击"宇树科技" | 展开详情：股价历史、供应商、历史销量；再点供应商展开其更多信息 | 复用时序快照与关系 |

### 10.2 第 1 天时序（创建 + 首次采集）

```
用户: 新建KB"机器人行业" → NL指令(主题/上下游/来源100)
系统: Planner解析 → 展示采集计划(上下游词表)供确认
用户: 确认
系统: Collector执行
        URL发现(~150候选) → URL级去重(首日基本不命中)
        抓取 → 内容/语义去重(剔除转载重复) → 抽取
        Graphify: 实体消歧 → MERGE写入Company/Industry/Component/...
        生成快照(股价/销量首日基线) + 溯源
        输出采集报告: 纳入N源, 去重M, 失败K
```

### 10.3 第 2 天时序（增量去重）

```
触发(定时或NL再次下达)
 → 载入KB采集计划
 → URL发现 → URL级去重(命中第1天已采集URL → 跳过)
 → 抓取剩余 → 内容/语义去重
 → 变化检测: 股价页内容已变 → 不丢弃, 追加MetricSnapshot(ts=第2天)
 → 仅新增节点/边写入
 → 报告: 新增X, 跨日去重Y, 新增快照Z
```

### 10.4 第 4 天时序（图形化逐层探索）

```
用户点击节点"宇树科技"(Company)
 → GET /node/{id}/expand?depth=1
 → 返回: 属性面板 + 邻居(供应商SUPPLIES, 产品PRODUCES, 指标HAS_METRIC, 新闻MENTIONED_IN)
 → 点击"股价"Metric → 渲染HAS_SNAPSHOT时序曲线(历史股价)
 → 点击某"供应商"Company → 再次expand → 展开该供应商的产品/指标/上游
```

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 抽取错误/幻觉 | 图谱污染 | 置信度阈值 + 人工复核 + 溯源可回滚 |
| 反爬/站点封锁 | 采集失败 | 双通道抓取、限速退避、可配置数据源 |
| 实体消歧错误 | 节点重复/错并 | 别名表 + 多特征匹配 + 复核队列 |
| 去重过度/不足 | 漏采或重复 | 三层阈值可调 + 去重审计日志 |
| NL2Cypher 误生成 | 错误答案/越权 | 只读白名单、参数化、Schema 约束、结果溯源 |
| 数据合规 | 法律风险 | 遵守 robots、保留来源、非投资建议声明 |

## 15. 里程碑建议（参考）

1. **M1 基础采集闭环**：单 KB、NL→计划、抓取、URL 级去重、基础建图。
2. **M2 去重与增量**：内容/语义去重、变化检测、时序快照、每日定时。
3. **M3 查询体验**：图形化探索 + 指标曲线 + NL2Cypher（含安全层）。
4. **M4 健壮与运营**：消歧增强、复核队列、监控、报告、成本优化。
