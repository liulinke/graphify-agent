# Claude Code 分阶段开发指令清单

按顺序，每条作为一次独立会话粘贴给 Claude Code。每条都让它在本阶段内「写代码 → 跑测试 → 修到全绿」自循环。
前置：仓库里已有 `CLAUDE.md`、`docs/服务端详细开发设计文档.md`、`docs/知识图谱采集Agent_软件需求说明书.md`。

---

## 阶段 0 —— 项目脚手架

```
阅读 docs/服务端详细开发设计文档.md 与 CLAUDE.md。用 uv 初始化项目（git init -b main、uv init、uv venv），
按设计文档第 2 章目录结构创建完整骨架：pyproject.toml、生成 uv.lock、.gitignore、.env.example、README.md、
所有空的包目录与 __init__.py、tests/unit 与 tests/integration 目录。
依赖用 uv 添加（uv add 运行时依赖；uv add --dev 测试依赖，含 pytest pytest-mock pytest-asyncio pytest-cov responses testcontainers[neo4j]）。
实现 graphify/config.py（pydantic-settings）和 graphify/llm.py（init_chat_model 封装）。
跑 `uv sync` 确认可安装，再跑 `uv run pytest` 确认能空跑通过。
```

## 阶段 1 —— 数据模型 + 去重模块（地基，纯逻辑）

```
按设计文档第 3 章实现 graphify/schemas/ 下的 plan.py、graph.py、query.py。
按第 6 章实现 graphify/dedup/ 下的 url_norm.py、simhash.py、semantic.py（语义层可先留接口+开关）。
按第 10.3 节为以上写齐单元测试：test_url_norm.py、test_simhash.py。

```

## 阶段 2 —— Neo4j 数据访问层（DAL）

```
按设计文档第 7 章实现 graphify/graphdb/（driver.py、dao.py、cql.py）和
graphify/store/source_repo.py（source/dedup_log/task 的关系库访问，去重指纹）。
单元测试用 mock driver/session（test_dao_cypher.py，断言生成的 Cypher 含 MERGE/参数、run_read 用 READ 模式）。
集成测试按第 10.5 节用 testcontainers 写 test_dao_neo4j.py（验证 append_snapshot 保留历史）。
跑 `pytest tests/unit -q` 全绿；若本机有 Docker 再跑 integration。
```

## 阶段 3 —— 工具层 + Planner + Collector

```
按设计文档第 5 章实现 graphify/tools/（search.py、fetch.py、dedup.py、extract.py、cypher.py）、
graphify/agents/planner.py、graphify/agents/collector.py。
fetch 用 httpx + BeautifulSoup（不要 Playwright）。check_duplicate 实现三层去重逻辑（第 6.3 节），
注意「URL 命中但内容变化」要返回 changed=True 而非判重。
按第 10.3 节写测试：test_planner.py、test_discover.py、test_filter_urls.py、test_collector_run.py、test_dedup.py。
所有 LLM/网络/repo 用替身（见第 10.2 节 FakeLLM/FakeDAO）。跑测试修到全绿。
```

## 阶段 4 —— Graph Builder + 主工作流

```
按设计文档第 5.4 章实现 graphify/agents/graph_builder.py（extract + persist，受控 schema、置信度阈值、消歧、时序追加）。
按第 4 章实现 graphify/state.py 和 graphify/graph_workflow.py（LangGraph StateGraph 编排 + checkpointer）。

```

## 阶段 5 —— Query Agent（NL2Cypher 安全护栏）

按设计文档第 5.5 章实现 graphify/agents/query_agent.py 和 graphify/tools/cypher.py 的 is_read_only。
重点：拦截任何写操作（CREATE/MERGE/DELETE/SET），强制 LIMIT 与 kb_id 过滤，参数化。
按第 10.3/10.4 节写 test_query_guard.py（写操作被拦截抛错、只读放行）和 test_query_answer.py。
跑测试修到全绿。
```

## 阶段 6 —— CLI

```
按设计文档第 9 章用 Typer 实现 graphify/cli/main.py，命令：
plan / discover / fetch / dedup / collect / ask / expand。
按第 10.4 节用 typer.testing.CliRunner 写 test_cli.py（mock 各 agent，断言退出码 0 与关键输出）。
跑 `pytest tests/unit -q` 全绿。最后跑一遍 `python -m graphify.cli.main plan kb_demo "采集机器人行业新闻，来源100"` 确认 CLI 可用。
```

对覆盖率低于 85% 的模块补测试。更新 README.md 写明安装、运行、测试、CLI 用法。
检查所有 TODO/占位实现，列出仍需真实接入的外部依赖（搜索 API、LLM key、Neo4j 连接）。
```

---

## 使用提示

- **一条一会话**：每个阶段开新会话，让上下文聚焦，避免越跑越乱。
- **卡住就缩小**：若某阶段测试反复不过，让它「只先让 test_xxx.py 通过」，逐个文件推进。
- **真实联调放最后**：前面全用替身跑通后，再单独配 `.env`（Neo4j、LLM key）做一次端到端 `collect` 真实运行。
